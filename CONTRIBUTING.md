# Contributing to SCALE4D

We welcome bug reports, documentation improvements, and pull requests.

## Pull requests

1. Fork the repository and create your branch from `main`.
2. Keep changes focused and explain the problem they solve.
3. Add or update tests when changing behavior, and update relevant documentation.
4. Describe how you validated the change and ensure the available checks pass.
5. Complete the Contributor License Agreement before your pull request is merged.

## Contributor License Agreement

To accept your pull request, we need you to submit a Contributor License
Agreement (CLA). You only need to do this once to contribute to Meta's open
source projects.

Complete your CLA at <https://code.facebook.com/cla>.

## Issues and security reports

Use GitHub issues for public bugs and feature requests. Include enough detail
to reproduce the problem, along with relevant environment information.

For security vulnerabilities, follow the disclosure process in
[Meta's bug bounty program](https://bugbounty.meta.com/) instead of filing a
public issue.

## Code of conduct

Participation in this project is subject to our
[Code of Conduct](CODE_OF_CONDUCT.md).

## License

By contributing to SCALE4D, you agree that your contributions will be licensed
under the license in [LICENSE](LICENSE).

Preserve copyright notices and disclaimers in third party code. When modifying
third party source, append `Copyright (c) Meta Platforms, Inc. and affiliates.`
to the file heading while retaining its original notices and license language.
Update the README and [third party notices](THIRD_PARTY_NOTICES.md) when adding
components governed by separate license terms, and include their original
license texts in `LICENSES/`. Keep the license texts and notices published in
`docs/` on `main` synchronized with the repository.

Maintainers must notify open source legal when adding a component licensed
under terms other than MIT, Apache 2.0, or CC0.
